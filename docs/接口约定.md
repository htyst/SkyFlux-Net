# 前后端接口约定

前端请求均是同源路径，不需要 API key。JSON 均为 UTF-8。网站在 `static/app.js` 的 `getJSON()` 里统一处理请求错误。

## `GET /api/status`

查询模型文件是否就绪。返回 200：

```json
{
  "models": [
    {"resolution": "5min", "label": "5 分钟", "lookback": 48, "available": true},
    {"resolution": "1h", "label": "1 小时", "lookback": 24, "available": true}
  ],
  "experimental": true
}
```

实际响应会有 `5min`、`1h`、`2h`、`1d`、`3d` 五项；`available` 根据 `models/` 中的文件实时计算。

## `GET /api/demo`

使用 `samples/` 下的五份历史数据调用真实模型，返回和预测接口相同的响应结构，`mode` 为 `demo`。此接口在页面“载入历史示例”按钮使用。完整真实响应示例见 `demo_response.json`。

## `POST /api/predict`

请求头 `Content-Type: application/json`。页面上传文件后先在浏览器读取文本，再把 CSV 文本放在 JSON 的 `csv` 字段中提交。

单尺度请求：

```json
{
  "csv": "datetime,bulkspeed,kp,e2,p1,p10\n2025-02-20 05:00:00,492.18,3.0,148.3443756,0.374,0.2451\n...",
  "mode": "direct",
  "resolution": "1h",
  "timezone": "UTC",
  "historical": true
}
```

- `mode`: `direct`（单尺度）或 `auto`（五分钟数据自动聚合多尺度）。`auto` 时 `resolution` 不参与计算。
- `resolution`: `5min`、`1h`、`2h`、`1d`、`3d` 之一。
- `timezone`: `UTC` 或 `Asia/Shanghai`。CSV 时间列本身不带时区。
- `historical`: 布尔值；`true` 用于演示旧数据并跳过时效检查。
- 请求体限制 24 MB，前端文件读取限制 23 MB，最多 300,000 行。CSV 列名和数值规则见根目录 README。

成功时返回 200，结构如下。`results` 中每个键对应一个可用尺度；`errors` 中每个键对应该尺度无法预测的原因。`auto` 模式可能部分成功。`direct` 模式只返回一个尺度，输入无效通常返回 HTTP 400。

```json
{
  "mode": "direct",
  "results": {
    "1h": {
      "resolution": "1h",
      "label": "1 小时",
      "last_observation": "2025-02-21T04:00:00",
      "timezone": "UTC",
      "input_count": 24,
      "lookback": 24,
      "baseline_flux": 0.2067,
      "baseline_alarm": "绿色",
      "predictions": [
        {"datetime": "2025-02-21T05:00:00", "step": 1, "flux": 0.226, "alarm": "绿色"}
      ],
      "recent_series": [
        {"datetime": "2025-02-20T05:00:00", "flux": 0.2451}
      ],
      "test_r2_log": null,
      "test_rmse_log": null,
      "historical": true
    }
  },
  "errors": {}
}
```

上面是**结构示意**，数值和数组长度以实际模型响应为准。完整真实结果见 `demo_response.json`。`predictions` 可能包含多步；前端卡片与图示目前只展示第一步，导出 CSV 包含全部步。

错误示例：`{"error":"CSV 缺少列：p10"}`。接口会返回 400（输入错误）、413（请求体过大）或 500（推理内部错误）。前端显示 `error` 字段原文，不能仅凭 HTTP 200 判断五个尺度全部成功。
