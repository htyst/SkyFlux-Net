# 页面与开发说明

## 页面结构

`static/index.html` 从上到下是：左侧导航和服务状态、首页视觉区、平台指标、数据输入、预测结果、模型说明、页脚。主要锚点是 `#top`、`#input`、`#results`、`#method`。

页面元素的 `id` 是 `static/app.js` 的绑定点。改动表单或结果区标签时，要同步检查脚本对这些 `id` 的引用。当前无需前端框架或构建工具。

## 前端逻辑入口

| 函数 | 作用 |
| --- | --- |
| `setMode()` | 切换五分钟多尺度与直接单尺度表单 |
| `readFile()` / `setCSV()` | 读取本地 CSV、更新文件信息 |
| `getJSON()` | 发起同源 API 请求并读取错误 |
| `predict()` / `demo()` | 提交用户输入或载入历史示例 |
| `drawResults()` / `selectResult()` | 渲染尺度卡片、详情与选中状态 |
| `chart()` | 生成内联 SVG 的 P10 曲线；纵轴是对数尺度 |
| `exportCSV()` | 把当前返回的预测结果导出为 UTF-8 BOM CSV |

样式在 `static/styles.css`。主题色定义在文件开头的 `:root`。窄屏断点目前是 1220、900、650、400 px。首页的轨道、发光球体和微动画全部是 CSS，没有外部图片依赖。

## 修改与联调

1. 只改颜色或布局：编辑 `static/styles.css`，刷新页面。
2. 改文字或结构：编辑 `static/index.html`，保留脚本依赖的 `id`，或同步修改 `static/app.js`。
3. 换接口实现：按 `接口约定.md` 保持 JSON 字段，尤其是 `results`、`errors`、`predictions`、`recent_series`。如果将前后端分开部署，配置 `/api/*` 反向代理和 CORS/认证策略。
4. 改结果逻辑：先核对 `static/app.js` 中卡片取 `predictions[0]` 和导出遍历全部 `predictions` 的区别。
5. 本地联调：运行完整服务，分别用“载入历史示例”和 `samples/1h.csv` 单尺度输入测试；旧数据要勾选“历史数据演示”。

## 交接时需要明确

- 本包的五个 `.pt` 模型用于本地复现；部署前需要确认模型版本、评估和数据来源。网页数据不会自动上传外部服务。
- 历史演示样本不代表实时输入。实时观测接口、图像融合和账户/权限功能均未实现。
- `reference_media/` 是目前的平台发布宣传片及封面，可用于向同学介绍目标视觉和操作流程；页面运行不读取这些文件。
- `只看前端.bat` 的静态服务可检视页面，但所有 `/api/*` 请求都会失败；需要完整演示时运行 `启动网站.bat`。
